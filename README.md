# Брайер

Курсовой проект. Тема работы:

> «ПРОЕКТИРОВАНИЕ И РАЗРАБОТКА ВЕБ-ПРИЛОЖЕНИЯ ДЛЯ КОЛЛЕКТИВНОГО
> ПРОГНОЗИРОВАНИЯ СОБЫТИЙ И ОЦЕНКИ ТОЧНОСТИ ПРОГНОЗОВ «БРАЙЕР»»

Пользователи задают вопросы о будущем и отвечают на них не «да» или «нет»,
а числом — своей вероятностью в процентах. После того как событие
наступило или не наступило, всем участникам начисляются очки по правилу
Брайера: чем увереннее и точнее прогноз, тем больше очков, чем увереннее
и ошибочнее — тем больше штраф.

Отдельно сервис показывает каждому участнику его **калибровку** —
насколько заявленная уверенность совпадает с реальной частотой попаданий.
Например: «когда вы говорите 90%, сбывается в 64% случаев».

Валюта — виртуальные очки. Денег в проекте нет ни в каком виде:
ни взносов, ни выигрышей, ни вывода средств.

## Откуда название

Правило Брайера — метрика точности вероятностных прогнозов, предложенная
метеорологом Гленном Брайером в 1950 году для оценки прогнозов погоды.
На ней построена вся система начисления очков в проекте.

## Статус

На сайте работают аккаунты, лента из PostgreSQL, создание вопросов и
раздел «Мои вопросы». В админке можно управлять категориями и модерировать
вопросы. Участник может сохранить или изменить прогноз до дедлайна.
После закрытия администратор указывает исход, а сайт начисляет очки по Брайеру.
Рейтинг, публичные профили и калибровка используют сохранённые результаты.
После дедлайна в карточке появляется прогноз модели, если к этому моменту
была обучена модель и в вопросе есть прогнозы участников. Гости могут
читать комментарии, участники — добавлять и удалять свои, администратор
может удалять любые комментарии в панели.

## Запуск демо для защиты

Из корня проекта:

```bash
bash run-demo.sh
```

Нужны Python 3.12+, PostgreSQL 16 и Node.js 20.19+. Скрипт создаёт
отдельную базу PostgreSQL, запускает сайт и проверку дедлайнов. Первый
запуск устанавливает зависимости. Сайт откроется по адресу
[127.0.0.1:5173](http://127.0.0.1:5173/). Логины и пароли двух
демо-аккаунтов появятся в терминале. Если порт 8000 занят, запусти `BRIER_DJANGO_PORT=8001 bash run-demo.sh`.
Остановка — Ctrl+C. Данные и пароли
сохраняются для следующего запуска в скрытой папке `.demo-local`.

Подготовленный сценарий содержит вымышленных участников, обсуждения, прогнозы
и исходы. `seed_demo` добавляет их при первом запуске и сохраняет существующие
карточки и аккаунты при повторном.

1. Войди как `brier-demo-user`. Открой вопрос про поиск заметок в «Полке»,
   сохрани прогноз и добавь комментарий.
2. В разрешённых вопросах ленты открой карточку о позднем показе «Тихого
   двора». В ней есть исход, прогноз группы и прогноз демомодели.
3. Открой рейтинг и профиль Веры Соколовой с графиком калибровки.
4. Войди как `brier-demo-admin`. В админке «Брайер» → «Вопросы» найди вопрос
   о двух вечерах в мастерской, если он ещё на модерации.

## Локальный запуск без демоданных

Для защиты проект запускается на ноутбуке. Нужны Python 3.12+, PostgreSQL 16
и Node.js 20.19+.

Подними PostgreSQL и создай базу `brier`. Для установки через Homebrew:

```bash
brew services start postgresql@16
createdb brier
```

В первом терминале из корня репозитория:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
python -c 'from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())'
```

Вставь полученную строку в `SECRET_KEY` в `backend/.env`. В значении используй
одинарные кавычки. Если у PostgreSQL отдельный пользователь или порт,
укажи их в том же файле. Затем в том же терминале:

```bash
set -a
source .env
set +a
python manage.py migrate
python manage.py seed_categories
python manage.py runserver 127.0.0.1:8000
```

Во втором терминале из корня репозитория:

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

- [Сайт](http://127.0.0.1:5173/)
- [Проверка API и базы](http://127.0.0.1:5173/api/health/) возвращает `{"status":"ok"}`
- [Админка](http://127.0.0.1:5173/admin/). Для входа создай администратора
  командой `python manage.py createsuperuser` в терминале с настройками Django.

Аккаунт можно создать на странице [регистрации](http://127.0.0.1:5173/register).
После входа нажми «Задать вопрос». Администратор может одобрить или отклонить
его в «Брайер» → «Вопросы». Отклонение требует причины. Одобренный вопрос
появится в ленте, решение видно автору в «Моих вопросах».
После дедлайна администратор открывает вопрос в панели и нажимает
«Указать исход». Он выбирает «Да» или «Нет» и добавляет источник. Участник
видит начисленные очки в карточке и в «Кабинет» → «Разрешённые».
Место в рейтинге появляется после 10 разрешённых прогнозов.
Калибровка доступна в кабинете и публичном профиле.

## Прогноз модели на защите

В терминале с активированным окружением Django и загруженными настройками:

```bash
python manage.py train_model --demo
python manage.py close_questions --watch
```

Первую команду запусти до дедлайна вопроса, на котором будешь показывать
модель. Она обучает её на искусственных примерах. Сайт помечает такой
прогноз. Вторая команда проверяет сроки каждые пять секунд. Для разовой
проверки запусти `python manage.py close_questions`. После закрытия
обнови карточку, чтобы увидеть сохранённый прогноз. После указания исхода
там же можно сравнить модель, группу и личный прогноз.

Для обучения на истории приложения нужны хотя бы 40 разрешённых вопросов
с прогнозами и оба исхода. Запуск — `python manage.py train_model` или
«Переобучить модель» в панели «Брайер» → «Вопросы». Отложенная проверка
выводит средний счёт Брайера модели и группы по одним и тем же вопросам.
