# Разбор по шагам

Каждый шаг разработки: какие файлы появились, как они связаны и как
объяснить их на защите. Читать сверху вниз — так проект и собирался.

---

## Этап «Вёрстка»

Цель этапа — внешний вид всех страниц и переходы между ними, без
настоящих данных. Источник — дизайн-макет на трёх ширинах: телефон 390 px,
планшет 834 px, десктоп 1440 px. Здесь из трёх макетов собрана одна
страница, которая перестраивается под ширину экрана.

### Шаг 1. Проект Vite, Tailwind, цвета и шрифт

**Файлы.**
- `frontend/package.json` — список библиотек и команды. `npm run dev`
  запускает сервер разработки, `npm run build` собирает готовые файлы
  в `dist/`. Версии записаны точно (`18.3.1`, без `^`), чтобы у всех
  ставилось одно и то же.
- `frontend/index.html` — единственная HTML-страница. В ней пустой
  `<div id="root">` и подключение `main.jsx`.
- `frontend/vite.config.js` — подключает к сборщику два плагина:
  React (понимает JSX) и Tailwind (собирает CSS из классов).
- `frontend/src/main.jsx` — точка входа: находит `#root` и рисует
  в нём React. Пока там пробная надпись; на шаге 4 её заменит `App`.
- `frontend/src/index.css` — подключает Tailwind, описывает шрифт и цвета.
- `frontend/src/fonts/` — три файла шрифта Onest и лицензия OFL.

**Как связано.** Браузер открывает `index.html` → тот подключает
`main.jsx` → `main.jsx` импортирует `index.css` → Vite с плагином
Tailwind превращает классы вроде `text-accent` в настоящий CSS.

**Что спросят на защите.**
- *Что такое `@theme`?* Блок Tailwind v4, где задаются свои токены.
  Строка `--color-accent: #2F45FF` даёт классы `text-accent`,
  `bg-accent`, `border-accent`. Цвет меняется в одном месте — меняется
  во всём приложении.
- *Зачем три файла шрифта?* Каждый содержит свой набор букв
  (кириллица, латиница, расширенная латиница). `unicode-range` говорит
  браузеру, какой файл нужен для каких символов, и он не качает лишнее.
- *Почему React 18, а не 19?* Так утверждено в стеке. Из-за этого
  React Router взят версии 7: восьмая требует React 19.

**Термины.**
- *Vite* — сборщик и сервер разработки: на лету отдаёт браузеру JSX и CSS.
- *JSX* — HTML-подобная разметка внутри JavaScript; вместо `class` пишется `className`.
- *Токен дизайна* — именованное значение (цвет, шрифт), которое используется везде вместо «голого» `#2F45FF`.

### Шаг 2. Демо-данные и формула очков

**Файлы.**
- `frontend/src/data/mock.js` — все данные, которые видны на страницах:
  участники, вопросы, комментарии, рейтинг, калибровка, мои вопросы.
  Перенесены из дизайн-макета. Здесь только данные, без логики, кроме
  одной функции `makeLeaderRow`.
- `frontend/src/utils/score.js` — две функции:
  - `calculatePoints(p, outcome)` → очки за прогноз по формуле
    `V = 100 · (1 − 2 · (p − o)²)`. Вход: прогноз в процентах и исход
    (1 или 0). Выход: целое число от −100 до +100.
  - `formatNumber(value, digits)` → строка с запятой: `61.8` → `«61,8»`.

**Как связано.** Страницы импортируют данные из `mock.js`, а очки
считают через `calculatePoints`. Очки в данных не записаны руками:
они всегда получаются из прогноза и исхода, как будет и на сервере.

**Что спросят на защите.**
- *Откуда данные, если нет backend?* Из `mock.js`. Поля названы так же,
  как будут называться в ответах API, поэтому на следующем этапе
  поменяется только место, откуда страница их берёт: `fetch` вместо `import`.
- *Почему ключ участника — имя пользователя?* Оно уникально и стоит
  в адресе профиля: `/users/alina.s`. Так по адресу сразу находится
  нужный участник: `people['alina.s']`.
- *Как из средних очков получается средний Брайер?* Очки и счёт Брайера
  связаны линейно: `V = 100 · (1 − 2B)`, отсюда `B = (1 − V/100) / 2`.
  Это и считает `makeLeaderRow`.
- *Проверка формулы:* 50 % даёт 50 очков при любом исходе; 80 % при
  исходе «Да» — 92; 90 % при исходе «Нет» — −62.

**Термины.**
- *Мок (mock)* — подставные данные, которые изображают ответ сервера, пока сервера нет.

### Шаг 3. Базовые элементы: логотип, аватар, кнопки

**Файлы** (папка `frontend/src/components/`).
- `Logo.jsx` — компонент `Logo`: знак на SVG и слово «брайер».
  Пропсы: `size` — размер знака, `showWord` — показывать ли слово
  (на планшете в боковой колонке только знак).
- `Avatar.jsx` — компонент `Avatar`: кружок с инициалами. Вход —
  участник (`person`) и размер. Функция `getInitials` берёт первые
  буквы двух слов имени. Цвет — по полю `tone` участника.
- `Button.jsx` — два компонента:
  - `Button` — кнопка с текстом. `variant` — вид (чёрная, с рамкой,
    серая), `size` — высота, `icon` — иконка слева, `full` — на всю ширину.
  - `IconButton` — круглая кнопка только с иконкой; `label` обязателен.

**Как связано.** Эти три файла — кирпичи для всех остальных блоков:
шапка, лента, кабинет собираются из них. Иконки берутся из пакета
`lucide-react` — это те же иконки Lucide, что в макете.

**Что спросят на защите.**
- *Почему кнопка иногда `<Link>`, а иногда `<button>`?* Если у кнопки
  есть `to`, она ведёт на другую страницу — это ссылка. Ссылка `<Link>`
  из React Router меняет страницу без перезагрузки. Без `to` это обычная
  `<button>`: на этом этапе она ничего не делает, действие появится,
  когда подключим API.
- *Чем `to` отличается от `href` у `IconButton`?* `to` — переход внутри
  React-приложения. `href` — обычная ссылка с перезагрузкой: так ведёт
  кнопка «Админ-панель», потому что админку отдаёт Django, а не React.
- *Зачем `aria-label`?* У круглой кнопки нет текста. Программа чтения
  с экрана для незрячих произнесёт `aria-label`, например «Выйти».
- *Что за запись `icon: Icon`?* Переименование при деструктуризации:
  проп называется `icon`, а внутри функции — `Icon`. В JSX компонент
  обязан начинаться с большой буквы, иначе React примет его за HTML-тег.
- *Почему классы хранятся в объектах `VARIANT_CLASSES`, `SIZE_CLASSES`?*
  Чтобы выбрать набор классов по названию варианта одной строкой,
  без цепочки `if`.

**Термины.**
- *Пропсы (props)* — входные параметры компонента, как аргументы у функции.
- *Деструктуризация* — `{ size, label }` в скобках функции: достать поля объекта в отдельные переменные.

### Шаг 4. Роутер и два лейаута

**Файлы.**
- `frontend/src/App.jsx` — главный компонент. В нём:
  - переменная `role` — роль пользователя (`'guest'`, `'user'`, `'admin'`).
    Пока входа нет, её меняют руками, чтобы показать разные варианты страниц;
  - список всех адресов (`<Route path=…>`) и какой компонент на каком
    адресе рисуется. Пока вместо страниц — заглушка `PagePlaceholder`,
    она исчезнет, когда будут свёрстаны все страницы.
- `frontend/src/layouts/MainLayout.jsx` — общая рамка страниц: позже
  в ней появятся шапка, навигация и подвал. `<Outlet />` — место, куда
  подставляется текущая страница. Проп `hideNav` прячет навигацию
  на странице создания вопроса.
- `frontend/src/layouts/AuthLayout.jsx` — рамка для входа и регистрации,
  без навигации. На телефоне — логотип и форма; на планшете — белая
  карточка по центру серого фона; на десктопе экран делится пополам:
  слева `promo`, справа форма.
- `frontend/src/main.jsx` — теперь рисует `<App />` вместо пробной надписи.
- `frontend/src/components/Logo.jsx` — размер знака теперь задаётся
  классом (`markClass`), чтобы он мог меняться по ширине экрана:
  `size-10 md:size-[34px]`.

**Адреса.**

| Адрес | Страница |
|---|---|
| `/` | лента вопросов |
| `/questions/:id` | вопрос; `:id` — часть адреса-переменная, например `snow` |
| `/questions/new` | создание вопроса |
| `/rating` | рейтинг |
| `/users/:username` | профиль участника |
| `/me`, `/me/resolved`, `/me/questions` | личный кабинет и его вкладки |
| `/login`, `/register` | вход и регистрация |
| `*` | всё остальное — страница 404 |

**Как связано.** `main.jsx` → `App` → `BrowserRouter` смотрит на адрес
в браузере → выбирает `<Route>` → рисует лейаут, а внутри него, на месте
`<Outlet />`, — страницу.

**Что спросят на защите.**
- *Что такое лейаут и зачем `Outlet`?* Лейаут — рамка, общая для многих
  страниц. Чтобы не повторять шапку и подвал в каждой странице, страницы
  вложены в `<Route element={<MainLayout />}>`, и React Router сам
  подставляет нужную страницу на место `<Outlet />`.
- *Почему у входа и регистрации два `AuthLayout`?* Рамка одна и та же,
  но левая половина на десктопе у них разная: у регистрации — пример
  начисления очков, у входа — калибровочная кривая. Эту картинку лейаут
  получает пропом `promo`.
- *Как одна страница становится тремя макетами?* Классы Tailwind
  с приставками: `md:` срабатывает от 768 px (планшет), `lg:` — от 1024 px
  (десктоп). Пример из `AuthLayout`: `bg-paper md:bg-canvas lg:bg-paper` —
  белый фон на телефоне, серый на планшете, снова белый на десктопе.
- *Почему `/questions/new` не принимается за вопрос с id «new»?*
  React Router сравнивает адреса и выбирает самый точный: постоянная
  часть `new` важнее переменной `:id`.

**Термины.**
- *Маршрут (route)* — правило «такой адрес → такой компонент».
- *SPA* — одностраничное приложение: браузер загружает одну HTML-страницу, а «страницы» меняет JavaScript без перезагрузки.
- *Брейкпоинт* — ширина экрана, с которой начинают действовать другие стили.

### Шаг 5. Шапка десктопа и поиск

**Файлы.**
- `components/Search.jsx` — поле поиска: иконка лупы и `<input>`.
  Пока только внешний вид, искать начнём с API. `<label>` вокруг
  иконки и поля нужен, чтобы клик по любой точке ставил курсор в поле.
- `components/DesktopHeader.jsx` — шапка десктопа. Три функции:
  - `MenuLink` — пункт меню «Вопросы» / «Рейтинг»;
  - `HeaderActions` — правая часть: зависит от роли;
  - `DesktopHeader` — собирает шапку: логотип, меню, поиск, правая часть.
- `layouts/MainLayout.jsx` — теперь рисует `DesktopHeader` над страницей.

**Роли в шапке.**
- гость — «Войти» и «Регистрация»;
- пользователь — «Задать вопрос», «Кабинет» с аватаром, «Выйти»;
- администратор — всё то же плюс ссылка «Админ-панель» на `/admin/`.

**Что спросят на защите.**
- *Как шапка понимает, какой пункт подчеркнуть?* `NavLink` из React
  Router сравнивает свой адрес с текущим и передаёт результат в функцию
  `className` как `isActive`. `end` значит «только точное совпадение»:
  иначе пункт «Вопросы» с адресом `/` горел бы на любой странице.
- *Почему шапки нет на телефоне?* Класс `hidden lg:block`: по умолчанию
  блок скрыт, от 1024 px — виден. На телефоне и планшете навигацию
  показывает другой компонент, `AppNav` (шаг 6).
- *Почему «Админ-панель» — `<a>`, а не `<Link>`?* `<Link>` переключает
  страницы внутри React. Админку отдаёт Django, это другая программа на
  сервере, поэтому нужна обычная ссылка с загрузкой новой страницы.
- *Что делает «Выйти»?* Пока только возвращает на ленту: настоящий выход
  — это запрос к серверу, он появится на этапе API.
