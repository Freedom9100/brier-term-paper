# Разбор по шагам

Каждый шаг разработки: какие файлы появились, как они связаны и как
объяснить их на защите. Читать сверху вниз — так проект и собирался.

---

## Этап «Вёрстка»

Цель этапа — внешний вид всех страниц и переходы между ними, без
настоящих данных. Источник — дизайн-макет на трёх ширинах: телефон 390 px,
планшет 834 px, десктоп 1440 px. Здесь из трёх макетов собрана одна
страница, которая перестраивается под ширину экрана.

### Шаг 1. Проект Vite, Tailwind, цвета и шрифт

**Файлы.**
- `frontend/package.json` — список библиотек и команды. `npm run dev`
  запускает сервер разработки, `npm run build` собирает готовые файлы
  в `dist/`. Версии записаны точно (`18.3.1`, без `^`), чтобы у всех
  ставилось одно и то же.
- `frontend/index.html` — единственная HTML-страница. В ней пустой
  `<div id="root">` и подключение `main.jsx`.
- `frontend/vite.config.js` — подключает к сборщику два плагина:
  React (понимает JSX) и Tailwind (собирает CSS из классов).
- `frontend/src/main.jsx` — точка входа: находит `#root` и рисует
  в нём React. Пока там пробная надпись; на шаге 4 её заменит `App`.
- `frontend/src/index.css` — подключает Tailwind, описывает шрифт и цвета.
- `frontend/src/fonts/` — три файла шрифта Onest и лицензия OFL.

**Как связано.** Браузер открывает `index.html` → тот подключает
`main.jsx` → `main.jsx` импортирует `index.css` → Vite с плагином
Tailwind превращает классы вроде `text-accent` в настоящий CSS.

**Что спросят на защите.**
- *Что такое `@theme`?* Блок Tailwind v4, где задаются свои токены.
  Строка `--color-accent: #2F45FF` даёт классы `text-accent`,
  `bg-accent`, `border-accent`. Цвет меняется в одном месте — меняется
  во всём приложении.
- *Зачем три файла шрифта?* Каждый содержит свой набор букв
  (кириллица, латиница, расширенная латиница). `unicode-range` говорит
  браузеру, какой файл нужен для каких символов, и он не качает лишнее.
- *Почему React 18, а не 19?* Так утверждено в стеке. Из-за этого
  React Router взят версии 7: восьмая требует React 19.

**Термины.**
- *Vite* — сборщик и сервер разработки: на лету отдаёт браузеру JSX и CSS.
- *JSX* — HTML-подобная разметка внутри JavaScript; вместо `class` пишется `className`.
- *Токен дизайна* — именованное значение (цвет, шрифт), которое используется везде вместо «голого» `#2F45FF`.

### Шаг 2. Демо-данные и формула очков

**Файлы.**
- `frontend/src/data/mock.js` — все данные, которые видны на страницах:
  участники, вопросы, комментарии, рейтинг, калибровка, мои вопросы.
  Перенесены из дизайн-макета. Здесь только данные, без логики, кроме
  одной функции `makeLeaderRow`.
- `frontend/src/utils/score.js` — две функции:
  - `calculatePoints(p, outcome)` → очки за прогноз по формуле
    `V = 100 · (1 − 2 · (p − o)²)`. Вход: прогноз в процентах и исход
    (1 или 0). Выход: целое число от −100 до +100.
  - `formatNumber(value, digits)` → строка с запятой: `61.8` → `«61,8»`.

**Как связано.** Страницы импортируют данные из `mock.js`, а очки
считают через `calculatePoints`. Очки в данных не записаны руками:
они всегда получаются из прогноза и исхода, как будет и на сервере.

**Что спросят на защите.**
- *Откуда данные, если нет backend?* Из `mock.js`. Поля названы так же,
  как будут называться в ответах API, поэтому на следующем этапе
  поменяется только место, откуда страница их берёт: `fetch` вместо `import`.
- *Почему ключ участника — имя пользователя?* Оно уникально и стоит
  в адресе профиля: `/users/alina.s`. Так по адресу сразу находится
  нужный участник: `people['alina.s']`.
- *Как из средних очков получается средний Брайер?* Очки и счёт Брайера
  связаны линейно: `V = 100 · (1 − 2B)`, отсюда `B = (1 − V/100) / 2`.
  Это и считает `makeLeaderRow`.
- *Проверка формулы:* 50 % даёт 50 очков при любом исходе; 80 % при
  исходе «Да» — 92; 90 % при исходе «Нет» — −62.

**Термины.**
- *Мок (mock)* — подставные данные, которые изображают ответ сервера, пока сервера нет.

### Шаг 3. Базовые элементы: логотип, аватар, кнопки

**Файлы** (папка `frontend/src/components/`).
- `Logo.jsx` — компонент `Logo`: знак на SVG и слово «брайер».
  Пропсы: `size` — размер знака, `showWord` — показывать ли слово
  (на планшете в боковой колонке только знак).
- `Avatar.jsx` — компонент `Avatar`: кружок с инициалами. Вход —
  участник (`person`) и размер. Функция `getInitials` берёт первые
  буквы двух слов имени. Цвет — по полю `tone` участника.
- `Button.jsx` — два компонента:
  - `Button` — кнопка с текстом. `variant` — вид (чёрная, с рамкой,
    серая), `size` — высота, `icon` — иконка слева, `full` — на всю ширину.
  - `IconButton` — круглая кнопка только с иконкой; `label` обязателен.

**Как связано.** Эти три файла — кирпичи для всех остальных блоков:
шапка, лента, кабинет собираются из них. Иконки берутся из пакета
`lucide-react` — это те же иконки Lucide, что в макете.

**Что спросят на защите.**
- *Почему кнопка иногда `<Link>`, а иногда `<button>`?* Если у кнопки
  есть `to`, она ведёт на другую страницу — это ссылка. Ссылка `<Link>`
  из React Router меняет страницу без перезагрузки. Без `to` это обычная
  `<button>`: на этом этапе она ничего не делает, действие появится,
  когда подключим API.
- *Чем `to` отличается от `href` у `IconButton`?* `to` — переход внутри
  React-приложения. `href` — обычная ссылка с перезагрузкой: так ведёт
  кнопка «Админ-панель», потому что админку отдаёт Django, а не React.
- *Зачем `aria-label`?* У круглой кнопки нет текста. Программа чтения
  с экрана для незрячих произнесёт `aria-label`, например «Выйти».
- *Что за запись `icon: Icon`?* Переименование при деструктуризации:
  проп называется `icon`, а внутри функции — `Icon`. В JSX компонент
  обязан начинаться с большой буквы, иначе React примет его за HTML-тег.
- *Почему классы хранятся в объектах `VARIANT_CLASSES`, `SIZE_CLASSES`?*
  Чтобы выбрать набор классов по названию варианта одной строкой,
  без цепочки `if`.

**Термины.**
- *Пропсы (props)* — входные параметры компонента, как аргументы у функции.
- *Деструктуризация* — `{ size, label }` в скобках функции: достать поля объекта в отдельные переменные.

### Шаг 4. Роутер и два лейаута

**Файлы.**
- `frontend/src/App.jsx` — главный компонент. В нём:
  - переменная `role` — роль пользователя (`'guest'`, `'user'`, `'admin'`).
    Пока входа нет, её меняют руками, чтобы показать разные варианты страниц;
  - список всех адресов (`<Route path=…>`) и какой компонент на каком
    адресе рисуется. Пока вместо страниц — заглушка `PagePlaceholder`,
    она исчезнет, когда будут свёрстаны все страницы.
- `frontend/src/layouts/MainLayout.jsx` — общая рамка страниц: позже
  в ней появятся шапка, навигация и подвал. `<Outlet />` — место, куда
  подставляется текущая страница. Проп `hideNav` прячет навигацию
  на странице создания вопроса.
- `frontend/src/layouts/AuthLayout.jsx` — рамка для входа и регистрации,
  без навигации. На телефоне — логотип и форма; на планшете — белая
  карточка по центру серого фона; на десктопе экран делится пополам:
  слева `promo`, справа форма.
- `frontend/src/main.jsx` — теперь рисует `<App />` вместо пробной надписи.
- `frontend/src/components/Logo.jsx` — размер знака теперь задаётся
  классом (`markClass`), чтобы он мог меняться по ширине экрана:
  `size-10 md:size-[34px]`.

**Адреса.**

| Адрес | Страница |
|---|---|
| `/` | лента вопросов |
| `/questions/:id` | вопрос; `:id` — часть адреса-переменная, например `snow` |
| `/questions/new` | создание вопроса |
| `/rating` | рейтинг |
| `/users/:username` | профиль участника |
| `/me`, `/me/resolved`, `/me/questions` | личный кабинет и его вкладки |
| `/login`, `/register` | вход и регистрация |
| `*` | всё остальное — страница 404 |

**Как связано.** `main.jsx` → `App` → `BrowserRouter` смотрит на адрес
в браузере → выбирает `<Route>` → рисует лейаут, а внутри него, на месте
`<Outlet />`, — страницу.

**Что спросят на защите.**
- *Что такое лейаут и зачем `Outlet`?* Лейаут — рамка, общая для многих
  страниц. Чтобы не повторять шапку и подвал в каждой странице, страницы
  вложены в `<Route element={<MainLayout />}>`, и React Router сам
  подставляет нужную страницу на место `<Outlet />`.
- *Почему у входа и регистрации два `AuthLayout`?* Рамка одна и та же,
  но левая половина на десктопе у них разная: у регистрации — пример
  начисления очков, у входа — калибровочная кривая. Эту картинку лейаут
  получает пропом `promo`.
- *Как одна страница становится тремя макетами?* Классы Tailwind
  с приставками: `md:` срабатывает от 768 px (планшет), `lg:` — от 1024 px
  (десктоп). Пример из `AuthLayout`: `bg-paper md:bg-canvas lg:bg-paper` —
  белый фон на телефоне, серый на планшете, снова белый на десктопе.
- *Почему `/questions/new` не принимается за вопрос с id «new»?*
  React Router сравнивает адреса и выбирает самый точный: постоянная
  часть `new` важнее переменной `:id`.

**Термины.**
- *Маршрут (route)* — правило «такой адрес → такой компонент».
- *SPA* — одностраничное приложение: браузер загружает одну HTML-страницу, а «страницы» меняет JavaScript без перезагрузки.
- *Брейкпоинт* — ширина экрана, с которой начинают действовать другие стили.

### Шаг 5. Шапка десктопа и поиск

**Файлы.**
- `components/Search.jsx` — поле поиска: иконка лупы и `<input>`.
  Пока только внешний вид, искать начнём с API. `<label>` вокруг
  иконки и поля нужен, чтобы клик по любой точке ставил курсор в поле.
- `components/DesktopHeader.jsx` — шапка десктопа. Три функции:
  - `MenuLink` — пункт меню «Вопросы» / «Рейтинг»;
  - `HeaderActions` — правая часть: зависит от роли;
  - `DesktopHeader` — собирает шапку: логотип, меню, поиск, правая часть.
- `layouts/MainLayout.jsx` — теперь рисует `DesktopHeader` над страницей.

**Роли в шапке.**
- гость — «Войти» и «Регистрация»;
- пользователь — «Задать вопрос», «Кабинет» с аватаром, «Выйти»;
- администратор — всё то же плюс ссылка «Админ-панель» на `/admin/`.

**Что спросят на защите.**
- *Как шапка понимает, какой пункт подчеркнуть?* `NavLink` из React
  Router сравнивает свой адрес с текущим и передаёт результат в функцию
  `className` как `isActive`. `end` значит «только точное совпадение»:
  иначе пункт «Вопросы» с адресом `/` горел бы на любой странице.
- *Почему шапки нет на телефоне?* Класс `hidden lg:block`: по умолчанию
  блок скрыт, от 1024 px — виден. На телефоне и планшете навигацию
  показывает другой компонент, `AppNav` (шаг 6).
- *Почему «Админ-панель» — `<a>`, а не `<Link>`?* `<Link>` переключает
  страницы внутри React. Админку отдаёт Django, это другая программа на
  сервере, поэтому нужна обычная ссылка с загрузкой новой страницы.
- *Что делает «Выйти»?* Пока только возвращает на ленту: настоящий выход
  — это запрос к серверу, он появится на этапе API.

### Шаг 6. Навигация телефона и планшета, подвал, мобильная шапка

**Файлы.**
- `components/AppNav.jsx` — навигация телефона и планшета, **один
  компонент на две раскладки**. На телефоне это панель внизу экрана
  (`fixed bottom-0`), на планшете — колонка слева (`md:sticky md:h-screen
  md:flex-col`), на десктопе скрыта (`lg:hidden`). Функции:
  - `NavItem` — пункт: иконка и подпись, активный жирнее;
  - `AskButton` — чёрная плитка «Задать вопрос» (только для вошедших);
  - `AppNav` — собирает пункты по роли: гостю вместо плитки и кабинета — «Войти».
- `components/Footer.jsx` — подвал: логотип, три ссылки, автор.
  На телефоне в столбик, с отступом снизу 104 px, чтобы нижняя панель
  не закрыла последнюю строку.
- `components/MobileHeader.jsx` — верхняя полоса телефона. Два вида:
  с логотипом (лента, рейтинг) и со стрелкой «назад» и заголовком
  (вопрос, профиль). Рисует её сама страница: в макете она на каждой
  странице своя.
- `layouts/MainLayout.jsx` — собирает рамку: шапка десктопа сверху,
  ниже `AppNav` и колонка со страницей и подвалом.

**Кто за что отвечает.** Общая навигация — шапка десктопа, нижняя
панель телефона, колонка планшета — живёт в `MainLayout`: она одинакова
на всех страницах. Страница рисует только свою верхнюю полосу на
телефоне.

**Что спросят на защите.**
- *Как одна навигация становится и нижней панелью, и боковой колонкой?*
  Одни и те же пункты, разные классы. Без приставки — раскладка телефона:
  `fixed bottom-0 flex` (строка внизу). С `md:` — планшета:
  `md:sticky md:top-0 md:h-screen md:flex-col` (столбец на всю высоту
  слева). С `lg:hidden` — на десктопе пропадает.
- *Что такое `sticky`?* Элемент прокручивается вместе со страницей, пока
  не упрётся в край, и дальше стоит на месте. Колонка планшета всегда
  видна, сколько ни листай.
- *Почему у `NavLink` содержимое — функция?* Чтобы поменять не только
  класс, но и толщину линии иконки: React Router передаёт в функцию
  `isActive`, и активная иконка рисуется линией 2.25 вместо 1.75.
- *Зачем `min-h-[calc(100vh-4rem)]`?* Чтобы на короткой странице подвал
  стоял внизу экрана, а не посередине. `100vh` — высота окна, `4rem` —
  высота шапки десктопа (64 px).

### Шаг 7. Метки: статус, чип, очки

**Файлы** (`frontend/src/components/`).
- `Status.jsx` — `Status`: плашка статуса («Приём закрыт», «Исход: Да»,
  «Отклонён»…). Все варианты описаны в объекте `STATUSES`: цвет, текст,
  иконка. Компонент берёт нужный по ключу `kind`.
- `Chip.jsx` — `Chip`: круглая кнопка фильтра ленты. Чёрная, если `active`.
- `Points.jsx` — два компонента:
  - `Points` — очки со знаком: зелёные выше 50, красные ниже, серые ровно 50;
  - `Percent` — число с уменьшенным знаком «%», как в макете.

**Что спросят на защите.**
- *Почему цвет очков считается от 50, а не от нуля?* Ответ «50 %» всегда
  даёт ровно 50 очков — это уровень «ничего не знаю». Зелёный значит
  «лучше, чем подбросить монетку», красный — «хуже».
- *Зачем объект `STATUSES` вместо `if`?* Девять статусов цепочкой `if`
  заняли бы сорок строк. Объект — это таблица «ключ → как выглядит»:
  новый статус добавляется одной строкой.
- *Почему минус «−», а не «-»?* Типографский минус одной ширины с плюсом,
  и столбец очков не «пляшет».

### Шаг 8. Вкладки, строка сведений, линейка вероятности

**Файлы** (`frontend/src/components/`).
- `Tabs.jsx` — `Tabs`: строка вкладок. Вкладка с `to` — ссылка на другую
  страницу (вкладки кабинета). Вкладка без `to` — кнопка, по нажатию
  вызывается `onSelect(номер)` (вкладки статусов в ленте).
- `Meta.jsx` — `Meta`: строка мелких сведений с иконками
  (участники, комментарии, время до закрытия).
- `Ruler.jsx` — два компонента:
  - `Ruler` — линейка вероятности: синяя полоса — мнение группы,
    чёрная риска — ваш прогноз, ромб — модель, точка на краю — исход;
  - `Legend` — подпись, какой знак что значит.

**Что спросят на защите.**
- *Как линейка тянется на любую ширину?* Все положения заданы
  в процентах: `style={{ width: '65%' }}` у синей полосы,
  `left: '70%'` у риски. Прогноз и есть процент, поэтому число из данных
  подставляется напрямую.
- *Почему `style`, а не класс Tailwind?* Tailwind собирает классы заранее,
  при сборке, а прогноз известен только при показе страницы. Для значений
  из данных используется `style`.
- *Что за `key` в списках?* React требует у каждого элемента списка
  уникальный `key`, чтобы понимать, какой элемент изменился. В `Tabs`
  ключ — название вкладки, в `Meta` — номер, потому что тексты могут
  совпасть.
- *Что значат двойные фигурные скобки `style={{ … }}`?* Внешние — «здесь
  JavaScript», внутренние — объект со свойствами CSS.

### Шаг 9. Графики на SVG

**Файлы** (`frontend/src/components/`).
- `Histogram.jsx` — гистограмма прогнозов: десять столбцов (1–10 %,
  11–20 % … 91–99 %), чёрная линия — ваш прогноз, синий треугольник
  под осью — мнение группы. Функция `getBinIndex(p)` — номер столбца
  для прогноза: `Math.floor((p − 1) / 10)`, так 1–10 → 0, 91–99 → 9.
- `CalibrationChart.jsx` — калибровочная кривая:
  - `toX`, `toY` переводят проценты в координаты рисунка;
  - `curve` — строка-путь ломаной через все точки (`M` — начать, `L` — линия до точки);
  - `getAxisAnchor` — крайние подписи оси прижаты к краю;
  - `HighlightNote` — выделенная точка с плашкой «заявили 90 % / сбылось 64 %».
- `CalibrationTable.jsx` — те же точки таблицей: уверенность, сколько
  сбылось, сколько прогнозов.

**Как графики подстраиваются под ширину.** Два разных способа:
- *Гистограмма* — все координаты в процентах (`x="12%"`, `height="40%"`).
  Ширина рисунка — весь блок, высота — `h-[132px] md:h-[168px]`.
  Столбцы тянутся, а текст и толщина линий остаются в пикселях.
  Так один компонент заменяет три макета: 358, 702 и 662 px.
- *Калибровочная кривая* — `viewBox`: рисунок считается в своих
  координатах (например, 358 × 300) и целиком масштабируется на ширину
  блока. Здесь это подходит: на всех макетах кривая примерно одного
  размера, 318–418 px, и текст почти не меняется.

**Что спросят на защите.**
- *Почему не Chart.js?* Записано в `decisions.md`: точное совпадение
  с макетом и каждую строку можно объяснить. Внутри — только
  прямоугольники (`rect`), линии (`line`), путь (`path`) и текст.
- *Почему `toY` вычитает?* В SVG ось Y идёт сверху вниз: y = 0 —
  верхний край. А на графике 0 % должен быть внизу. Поэтому
  `toY = верх + высота − процент · высота`.
- *Зачем вложенный `<svg>` у треугольника?* У `<path>` нельзя задать
  координаты в процентах. Вложенный `<svg x="71%">` ставит начало
  координат в нужную точку, а треугольник рисуется от неё.
- *Как читать калибровочную кривую?* Диагональ — идеал: сказал 70 % —
  сбылось 70 %. Точка ниже диагонали — переуверенность: заявили 90 %,
  а сбылось 64 %. Чем крупнее точка, тем больше прогнозов за ней.

**Термины.**
- *SVG* — векторная графика прямо в разметке: фигуры задаются координатами и не размываются при увеличении.
- *viewBox* — «окно» в координаты рисунка; браузер растягивает это окно на размер элемента.

**Первый `useState` в проекте.** Вкладки «Открытые / Приём закрыт /
Разрешённые» переключаются:
```js
const [activeTab, setActiveTab] = useState(0);
const shownQuestions = Object.values(questions)
  .filter((question) => question.status === STATUS_BY_TAB[activeTab]);
```
`activeTab` — номер открытой вкладки, `setActiveTab` — функция, которая
его меняет. `Tabs` вызывает её при нажатии, React заново рисует страницу,
и `filter` оставляет только вопросы нужного статуса. Без этого
разрешённые вопросы были бы недоступны из ленты.

**Как одна страница становится тремя макетами.**
- *Телефон:* всё в один столбец, без заголовка «Вопросы» (его роль
  играет шапка).
- *Планшет (`md:`):* появляется заголовок с полем поиска; отступы 24 px.
- *Десктоп (`lg:`):* `lg:flex` ставит рядом две колонки: список
  (`flex-1`) и боковые панели (`w-[376px]`). Список оборачивается в
  белую панель классами `lg:bg-paper lg:rounded-[24px] lg:border`.
  На 1440 px это ровно 728 + 376, как в макете.
- *Приветствие гостя* — сетка (`grid`). На телефоне блок-пример стоит
  между текстом и кнопками. На планшете `md:col-start-2 md:row-start-1
  md:row-span-3` переносит его во вторую колонку справа. На десктопе
  заголовок растягивается на обе колонки (`lg:col-span-2`), а пример
  встаёт под ним справа.

**Что спросят на защите.**
- *Что делает `useState`?* Хранит значение, которое меняется на экране.
  Когда вызывается функция-сеттер, React перерисовывает компонент с новым
  значением.
- *Почему фильтры по категориям не работают, а вкладки работают?*
  Вкладки нужны, чтобы попасть на закрытые и разрешённые вопросы — это
  переход между страницами. Фильтры и поиск — функциональность
  следующего этапа, вместе с запросами к API.
- *Откуда «49 открытых»?* Сумма открытых вопросов по категориям через
  `reduce`: идёт по массиву и складывает `count`.
- *Почему боковые панели не видны на планшете?* `hidden lg:flex` —
  колонка скрыта и появляется только от 1024 px, где для неё есть место.

**Термины.**
- *Состояние (state)* — данные компонента, которые меняются, пока страница открыта.
- *CSS Grid* — раскладка сеткой: элементы ставятся в строки и колонки, и их можно переставлять, не меняя порядок в разметке.

### Шаг 13. Блоки вопроса: сравнение, формула, комментарии

**Файлы** (`frontend/src/components/`).
- `Comparison.jsx` — два компонента:
  - `Comparison` — «Кто был ближе к исходу»: линейка с исходом и таблица
    «вы / группа / модель» с очками каждого. У лучшего — метка «ближе всех».
    `getVerdict` пишет вывод: кто точнее — группа или модель — и на сколько очков;
  - `ScoreFormula` — формула `V = 100 · (1 − 2 · (p − o)²)` и подстановка
    в неё вашего прогноза. Гостю — только формула, без подстановки.
- `Comments.jsx` — комментарии:
  - `CommentsSection` — заголовок с числом, поле ввода (не для гостя),
    список и кнопка «Показать ещё N»;
  - `Comment` — один комментарий: автор (ссылка на профиль), метка «автор»,
    если пишет автор вопроса, прогноз комментатора; у своего — корзина;
  - `CommentInput` — поле нового комментария.

**Что спросят на защите.**
- *Как находится «ближе всех»?* Для каждой строки считаются очки
  `calculatePoints(p, исход)`, затем `Math.max` по всем строкам. Метку
  получает строка, чьи очки равны максимуму. Больше очков — значит ближе
  к исходу: формула штрафует за квадрат расстояния до исхода.
- *Почему у гостя нет строки «Вы»?* У гостя нет прогноза, сравнивать
  нечего. Строки собираются в массив `rows`, и «Вы» добавляется только
  при `showYou`.
- *Почему корзина есть только у своего комментария?* По ТЗ пользователь
  удаляет только свои комментарии, а чужие — администратор в админке Django.

**`useParams` — единственное исключение из правила хуков.**
В проекте разрешены только хуки `useState` и `useEffect`. `useParams` —
хук из React Router, без него не узнать, какой вопрос открыт: адрес
`/questions/snow` превращается в `{ id: 'snow' }`, и по этому `id`
страница находит вопрос — `questions[id]`, а на следующем этапе —
запросом `fetch('/api/questions/snow/')`. Заменить его нечем: номер
вопроса есть только в адресе. Это исключение утверждено отдельно и
записано в `decisions.md`. Тот же хук понадобится профилю (`/users/:username`).

**Одна страница — три состояния.** Открытый, закрытый и разрешённый
вопрос — не три страницы, а один компонент: он смотрит на
`question.status` и выбирает блоки в `QuestionBody`. Когда появится API,
состояние будет приходить с сервера, а код страницы не изменится.

**Что спросят на защите.**
- *Что будет по адресу `/questions/abc`?* `questions['abc']` вернёт
  `undefined`, и страница покажет «Вопрос не найден» (на шаге 20 —
  полноценная страница 404).
- *Зачем константа `SECTION`?* Отступы разделов одинаковые на всей
  странице: 16 px на телефоне, 24 на планшете, 32 на десктопе. Строка
  классов записана один раз, а разделы подставляют её через `${SECTION}`.
- *Почему формула на десктопе в боковой колонке, а на телефоне — в ленте
  страницы?* Так в макете: на десктопе для неё есть место сбоку. В ленте
  раздел скрыт классом `lg:hidden`, а в колонке `QuestionAside` он есть.
- *Что видит гость?* Мнение группы и гистограмму без своей риски,
  вместо формы — «Войдите, чтобы поставить прогноз», в сравнении — только
  группа и модель, комментарии без поля ввода.

**Как таблица перестраивается.** На телефоне у строки три части: место,
участник, средние очки; Брайер и число прогнозов — мелкой строкой под
именем (`md:hidden`). От планшета эта строка прячется, а Брайер и число
прогнозов встают в свои столбцы (`hidden md:block w-24`), под именем —
`@логин`. Ширины столбцов в шапке и в строках одинаковые, поэтому
числа стоят ровно друг под другом.

**Что спросят на защите.**
- *Почему рейтинг по среднему, а не по сумме?* Ответ «50 %» всегда даёт
  50 очков. При сумме выгодно отвечать «50 %» на всё подряд. Среднее этот
  обход закрывает: стратегия «всегда 50 %» даёт ровно 50 — строку «монетки»
  внизу таблицы.
- *Как считается «ещё N участников»?* `to − from + 1`: места с 15 по 86 —
  это 86 − 15 + 1 = 72 участника.
- *Как выбирается окончание слова «участник»?* По последней цифре
  числа: 1 — «участник», 2–4 — «участника», остальное — «участников».
  Исключение — 11–14: там всегда «участников».

  с очками; заголовок — ссылка на вопрос, если он есть в данных) и
  `HiddenForecastsNote` («Прогнозы по открытым вопросам скрыты»).
- `components/Avatar.jsx` — новый проп `className` для другого размера
  на планшете: `md:size-[84px]`.
- `App.jsx` — адрес `/users/:username` ведёт на `ProfilePage`.

**Как раскладка меняется по ширине.**
- *Аватар:* на телефоне справа от имени, от планшета — слева.
  В разметке он стоит первым, а класс `order-last md:order-first`
  переставляет его в конец строки на телефоне.
- *Калибровка и прогнозы:* телефон — друг под другом; планшет — две
  колонки (`md:flex`, калибровка 330 px слева); десктоп — снова друг
  под другом, но каждая в своей белой панели (`lg:block`).
- *Внутри калибровки на десктопе* — сетка: кривая слева на две строки,
  справа текст и таблица. Классы `lg:col-start-…` и `lg:row-start-…`
  ставят блоки в клетки сетки, не меняя порядок в разметке.

**Что спросят на защите.**
- *Почему в профиле нет открытых прогнозов?* Их можно было бы
  подсмотреть и списать. Решение от 25.09 в `decisions.md`.
- *Как ищется участник?* `people[username]` — сам участник,
  `[...leaderboard, myRow].find(...)` — его строка рейтинга (место, очки).
  `...` — оператор «разложить»: склеивает массив лучших и строку
  текущего пользователя в один массив.
- *Что если адрес неверный, например `/users/nobody`?* Участник не
  найдётся, и страница покажет «Участник не найден».
